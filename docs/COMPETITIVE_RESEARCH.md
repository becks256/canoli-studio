# Competitive evidence and positioning

Research date: 2026-09-21. Method: inspect official product/help/standards pages and compare their stated capabilities with the current Luma source. This is a documentation audit, not hands-on competitor testing. Availability can differ by device, region, plan, release or beta; recheck before a launch claim. We did not purchase subscriptions or run comparative quality/performance benchmarks. Prices and model unit costs are intentionally not asserted.

## Metadata and provenance references

[IPTC's Photo Metadata Standard](https://iptc.org/standards/photo-metadata/iptc-standard/) defines interoperable descriptive fields and technical representations. Its 2025.1 release adds fields for AI prompt information, prompt writer, system and version. Luma should map reviewed values to supported standard fields rather than invent incompatible replacements. Asset metadata and document composition metadata are distinct; inspect each export format's actual embedding support.

[C2PA's explainer](https://c2pa.org/specifications/specifications/2.2/explainer/Explainer.html) distinguishes tamper-evident provenance from judgments about factual truth. Luma's initial local generation log is not signed Content Credentials. Verification/signing requires a separately scoped implementation, trust handling and interoperability tests. Absence of credentials must not be shown as evidence of fakery.

[IPTC's AI metadata release note](https://iptc.org/news/iptc-photo-metadata-standard-2025-1-adds-ai-properties/) includes an example where metadata editing invalidates existing credentials. Preserve the original asset and treat derivative-file credentials deliberately; do not copy a source signature to changed bytes and label it valid.

These standards references inform engineering, not legal advice or a guarantee of rights. File copyright/license declarations may be inaccurate; AI cannot determine ownership by looking at pixels.

## Positioning hypotheses to validate

| Hypothesis                                                                     | Evidence needed                                                                                 | What would weaken it                                                                   |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Users will switch for protected source content plus faster variant production. | Timed side-by-side tasks, pixel/identity checks, repeat paid use.                               | Incumbent workflow is equally fast, or outputs regularly alter labels/artwork.         |
| Correctable metadata and asset search remove enough catalog work to matter.    | Blind review precision, corrections per image, retrieval success and minutes saved.             | Caption cleanup takes as long as writing manually, or users already have a better DAM. |
| OOP recipes connect manual and AI work better than disconnected services.      | Users parameterize and rerun a workflow on new images without developer assistance.             | Every run needs custom scripts or manual target rebinding.                             |
| Browser convenience with local project ownership reduces friction.             | Import/recovery/export success on real devices; users can move work without losing editability. | File compatibility, memory, offline or color limitations prevent professional handoff. |

## Next hands-on comparison protocol

Use the same source files, output requirements and preservation regions. Record tool versions, available features/plans, hardware, full task time, rejected candidates, corrections, generation spend, unsupported import elements, and final output quality. Have users assess exported artifacts without knowing which editor produced them where feasible. Publish failures alongside wins; reproduce regressions before promoting a feature claim. Research and benchmark refresh is a gate for each major release, especially after competitors change generation or interoperability capabilities.
