## Affine coordinates and masks

`core/affine.ts` exposes the immutable public `AffineTransform` value using double-precision coefficients `[a c e; b d f; 0 0 1]` and column vectors. `parent.multiply(child)` applies the child first. Positive rotation is clockwise in the downward-positive editor plane. Inverse operations reject singular matrices; extremely ill-conditioned transforms may be singular at working precision.

Layer DTOs store x/y translation separately from an optional invertible basis with zero e/f. `core/spatial.ts` composes `translation(x,y).multiply(basis)` and accumulates parent matrices. DOM `Layer.transform` reads and writes the full local-to-parent transform, splitting its translation into x/y through one validated update. Raster width/height remain placed geometry, not a request to resample original source bytes. Layer selection supports translation, alignment, distribution, rotation, scaling and flipping through shared commands, with selected descendants excluded when their ancestor is also selected.

Canvas and WebGPU composition, inverse hit testing, tool coordinate conversion, transformed layer bounds and mask rendering consume composed matrices. `engine/canvas.ts` rebases translation against the tile origin in double precision before scaling. Cache placement signatures include the matrix. Reparenting and cross-document transfer preserve world placement through coordinate conversion; source assets remain immutable. Perspective and general warp are not implemented by the affine matrix model.

`core/masks.ts` composes linked mask geometry with the complete layer matrix; unlinked masks remain in document space. `Layer.setMaskLinked` converts offsets and basis to retain world placement. A literal mask DTO replacement does not perform that conversion. Selection/path capture maps geometry between source and target planes, including Bézier handles. Feather remains a document-pixel coverage operation after geometry transformation, so scaling geometry does not scale the feather radius. Rotation/scaling of layer or mask planes is distinct from bitmap-mask import and other unfinished mask tools.

Read [PRODUCT_BRIEF.md](./PRODUCT_BRIEF.md) for intent and [API.md](./API.md) for both automation surfaces. Luma is a working name.

## Object identity and transactions

Constructors create detached objects. Adding to a document or owned group establishes ownership. A layer cannot belong to two documents, and groups cannot create cycles. Attached handles resolve their stable ID in the current revision, so retained handles reflect undo/redo. Access to a removed node throws until it exists again. Duplicates have independent node/effect IDs and share the original source asset. Constructor-driven duplicate commands include an ID mapping so replay in a script's host produces the same references.

`Document.transaction(label, callback)` is synchronous, atomic and one undo entry. Nested transactions and async callbacks are unsupported. Do not schedule asynchronous mutation from a transaction; prepare asynchronous results first. Failed transactions discard document changes; handles created during a failed transaction must be discarded. Active-layer selection (`selectedLayer`) is session state and does not create history. Pixel selection (`selection`) is undoable document content. History retains up to 60 metadata revisions, not copied pixel arrays.

The underscore-prefixed methods are internal adapters, not supported external API. DTOs are for serialization and transport, not direct mutation. Current document schema 15 adds HSL adjustments; supported older documents migrate after validation. Unknown layer/effect kinds and fields unsupported by a reader fail rather than silently disappearing.

## Resolution and memory

**No fixed megapixel, image-byte-size, session-pixel-count, or 8192-pixel import cutoff.** User requirement: modern high-resolution images retain their original dimensions and source data. Document integer dimensions need only be positive and safely representable in JavaScript; this is a numeric representation constraint, not a product-resolution tier.

Working allocations are independent of document size:

- The browser decodes the original image with `createImageBitmap`; original compressed bytes are retained as immutable blobs for the v3 project container. Images are never silently resized on import. Layer placement may fit an image within an existing composition without modifying its source.
- The viewport renders only the visible document region. Zooming to 100% requests the corresponding source-resolution region. Screen buffers use a 4 MP / 4096-pixel-side allocation budget, not an import limit. Very dense/high-DPI viewports can use a reduced working preview.
- Each tone operation runs on tiles no larger than 1024 × 1024 in a worker. Tone and Blend If are point operations and require no halo. Drop shadows render padded regions that include blur/offset contributions across tile boundaries; verify seams against a full-region reference.
- Group opacity and blending apply once to an isolated group buffer for the current region. Intermediate canvases are released after compositing.
- PNG export renders full-resolution tiles and feeds rows into `CompressionStream('deflate')`. It never creates a document-sized output canvas. Scanline strips target about 4 MB; compressed PNG chunks remain in memory until download. Format dimension restrictions are export-format constraints, never image import limits.
- Thumbnails use small separate images, avoiding a second full-size decode per layer row.

This is **not** a claim of infinite-size support: browser decoding still materializes the source bitmap; original image assets remain resident for undo; the document manifest still materializes JSON; legacy `.luma` JSON/base64 imports still allocate large strings. Device memory, browser decoders, numeric representation, and output formats impose real constraints. Recoverable decoder/allocation failures must report the actual operation, not invent an MP cutoff. A browser process killed by its OS cannot be caught reliably.

Next scaling boundary: lazy/region-capable image decoding, disk-backed asset storage and caches, streaming manifest/asset I/O beyond the current blob container, cancellation/progress, and expanded GPU coverage where measured performance justifies it. Do not reintroduce document caps to compensate for whole-image buffer allocation. Test 50 MP end to end and dimensions beyond prior cutoffs in model/API tests.

At reduced preview scale, adjustments operate on the resampled working pixels; nonlinear clipping can differ from final full-resolution export. Source-size crops and export use full-resolution processing. The first kernel uses encoded sRGB 8-bit channels; linear-light processing, ICC fidelity, RAW, CMYK and HDR need explicit future design.

## Tools and extended document content

`ToolController` tracks gestures, settings, command previews and a separate transient paint preview. Brush/pencil input accumulates all delivered/coalesced pointer samples, while preview publication is limited to one animation frame. A new empty paint layer is placed with the existing commands once at gesture start; subsequent samples never clone or validate the whole document. Pointer release includes the final endpoint and creates one validated DOM transaction. Escape, focus loss or session replacement cancels the gesture, including in-flight clone capture; a generation counter and document revision prevent stale commits. New paint/vector layers are placed above the selection or inside a selected group with document coordinates preserved. Preview placement uses the same commands.

Paint operations are immutable metadata (points, pressure, clip, style, source-tile references). Each operation renders into the current region, then its opacity applies once. Pencil uses pixel-aligned stamps. Clone snapshots the visible composition in at-most-1024px tiles before committing; staged assets are removed on cancellation/failure. Committed assets remain available for undo, and project serialization includes assets referenced by both rasters and clone operations. Stroke IDs and path IDs regenerate on duplication; original source assets remain shared.

Vectors store anchors and absolute local Bézier handles, stroke/fill and closure. Attached paths resolve by ID. Marquee regions evaluate ordered Boolean operations into a 4×4 subpixel mask in the WASM worker, with consistent coordinates across tiles; strokes capture that selection in local coordinates. New optional selection/style/fill-opacity fields are additive in prototype schema 1, with defaults for old files. Older builds may reject paint/vector layer kinds rather than silently discard them.

The region compositor isolates content, builds a shadow with padding, adds the color overlay, applies fill opacity to content, applies WASM Blend If to the styled result against preceding siblings, then composites with layer opacity/blend mode. Group child Blend If sees that group's internal backdrop. Color overlay and shadow pixels are browser Canvas operations; per-pixel tonal gates execute in the WASM worker.

`npm run build:docs` converts repository Markdown into local HTML/CSS under `public/developer`. Both `dev` and `build` generate these pages. The canonical source remains `docs/`; source-file references are labeled as repository references in the generated pages.

## Interactive rendering caches

`ActiveStrokeRaster` retains one unmasked brush/pencil canvas and draws only newly appended segments with the same stamp grid as full replay. It composites a copy with the captured selection mask and stroke opacity once, then feeds the normal layer/group/effect compositor. This preserves pressure, soft edges, translucent overlaps and export parity. A changed stroke/settings, rewritten or shortened point prefix, transform, viewport or scale resets the surface. The active surface retains at most 16 MiB; larger effect halos use full replay without imposing a document-size limit.

`CanvasCache` retains up to 64 MiB (and 64 entries) of least-recently-used layer content and active selection-mask canvases. Keys include the document, asset store, complete layer content, absolute placement and render space. Frozen layer signatures are memoized by object identity. Content is cached before its own styles; backdrop-dependent Blend If always runs against the current composition. Ancestors containing a live stroke recompose their children. Reads/writes copy synchronously, so asynchronous jobs cannot retain references to evicted buffers. Session replacement/disposal clears retained pixels and prevents in-flight jobs from repopulating an obsolete cache.

`RenderOptions.paintPreview` is an internal trusted tool/render adapter, not a scripting or REST mutation API. Export and clone sampling pass `cache: false` to avoid replacing useful viewport entries with one-off tiles. The same option provides the full-replay reference in renderer regression tests. Completed strokes remain editable metadata; the cache is neither persisted nor part of history. Stroke commit can still replay a changed paint layer once, and complex shadows/Blend If still cost work per frame; there is no universal frame-rate guarantee.

Browser tests in `tests/rendering.e2e.ts` cover pixel parity, segment work, frame batching, final samples, cancellation, cache eviction, and tone invalidation. The existing high-resolution import/export and tiled-effect tests remain required.

## GPU viewport backend

`AdaptiveRenderer` preserves `CanvasRenderer.render()` for export, clone capture and reference pixels. Its `prepareViewport()` selects `WebGpuRenderer` when a hardware adapter is available in a secure context (HTTPS or localhost), and otherwise prepares a Canvas/WASM frame. Software adapters are rejected in normal operation; an internal constructor option permits them in shader tests. This does not require a backend server, cloud upload, paid service or document-model change.

GPU viewport behavior:

- Source images are drawn into **visible-region** buffers before upload, never into a GPU texture sized to the entire imported image. Unchanged raw raster, paint and vector content stays in an LRU texture cache. Tone changes reuse the original uploaded raster.
- WGSL implements incremental brush/pencil stamps using the shared stamp-spacing iterator, tone adjustments, captured Boolean selection masks, color overlay/fill opacity, isolated group compositing, all 16 blend modes, and source/underlying Blend If. Brush coordinates are rebased in JS double precision before entering GPU buffers. Stroke opacity and clipping apply once to the accumulated surface.
- Fill/clear, clone and vector primitives currently use reference rasterization on a cache miss and then retain their uploaded texture. Drop-shadow documents use the complete Canvas/WASM path; GPU blur is not implemented. Brushes with projected stamp diameters below two working pixels use the reference path so supersampling cannot erase subpixel marks. These are backend choices, not document/tool restrictions.
- RGBA8 textures use premultiplied alpha and encoded sRGB. GPU preview and committed GPU strokes match; Canvas/export comparisons allow small 8-bit rounding and edge-antialiasing differences. The tested stacked-effect fixture differs by at most four channel values; the tested soft-brush edges by at most eleven, with mean error below 0.1. Do not describe the two backends as bit-identical or claim universal tolerances from these fixtures.
- Cached textures retain at most 64 MiB and 64 entries, plus at most 16 MiB for an active stroke. Renderer-owned live textures have a 192 MiB working budget. These exclude browser/driver overhead, source decoding, Canvas fallback allocations, diagnostic readback buffers and the browser-owned swapchain. Device texture limits, allocation/validation failures and precision-sensitive masks trigger fallback rather than resizing/rejecting the document.
- `ViewportFrame.present()` writes directly to a WebGPU canvas after the UI checks its render generation. It does not read pixels back to the CPU. The host replaces the canvas when switching backend because context types cannot be changed in place. Device-loss notifications request a fresh fallback frame automatically. Session replacement clears caches and invalidates pending frames; every prepared frame must be disposed.

The Canvas factory defaults to drawing surfaces without `willReadFrequently`; tone readback tiles, Blend If buffers and PNG readback explicitly request CPU-friendly buffers. Drawing surfaces no longer read back a probe pixel on allocation. The reference renderer continues to run per-pixel CPU operations in the WASM worker.

The footer reports **GPU accelerated** or **Standard rendering** for the displayed frame. Trusted development code can inspect `editor.renderer.gpu.diagnostics` (state, cumulative uploads/stamps/cache hits/frames/readbacks and retained/allocated bytes). This is an internal diagnostic, not a scripting or REST API. `ViewportFrame.readPixels()` exists for explicit GPU test readback only; ordinary viewport rendering does not call it.

`tests/webgpu.e2e.ts` runs actual WGSL through Chromium's SwiftShader adapter and reads GPU output buffers to check pixels, texture reuse, large-document regions and device-loss recovery. The presentation shader is separately tested against a real GPU texture in the preferred canvas format. The current headless software-adapter environment cannot present a browser-owned WebGPU swapchain canvas reliably; hardware presentation and hardware performance must be checked on a real GPU. Shader tests are not proof of hardware speedup. The regular browser/production suites exercise the automatic Canvas fallback, gestures and exports.

Reference: [WebGPU specification](https://gpuweb.github.io/gpuweb/), [canvas readback contexts](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/getContext#willreadfrequently).

## Parameter controls

`src/ui/controls.tsx` owns the shared slider/number pair. Both tool options and bounded inspector properties use it. Tool previews update session settings directly; document-property previews remain transient commands until the gesture commits through the DOM. The control tracks pending gestures separately from committed values, so release followed by blur does not duplicate history. Path-width previews use the same command preview path as layer/tone/style adjustments. See the design system for keyboard, numeric-validation and scale rules.

## Asynchronous work

Reference-renderer pixel buffers transfer to a dedicated worker and back; the main thread does not execute WASM pixel loops. The adaptive viewport uses GPU shaders when supported and the Canvas compositor otherwise. A serial preview drain starts at most one render per animation frame and takes the newest queued snapshot. It rejects stale revisions, viewports and cancelled/replaced gestures; an earlier prefix of the same live stroke may display while its next frame waits, avoiding starvation during expensive effects. Cursor updates are frame-paced too. Export uses the same region compositor at source scale. Replacing a session releases its assets; callers should finish asset-dependent work before replacing a session.

The constructor API is TypeScript, not compiled to WASM. AssemblyScript is a separate, constrained TypeScript-like language used only for the numeric kernel. It is replaceable behind the worker protocol. The GPU viewport backend and Canvas reference/export renderer share document snapshots without changing the public DOM or document schema.

## Scripting boundary

See [SCRIPTING_API.md](SCRIPTING_API.md) for the public scripting contract, reference and runnable examples.

A sandboxed opaque-origin iframe creates a dedicated worker containing the bundled DOM implementation. The script receives a document snapshot, selected ID and constructor bindings, never host object references, credentials or image bytes. CSP denies network and external code loading. The host validates returned commands, checks that the document/revision has not changed, validates referenced assets, and commits one atomic transaction. A thrown error, invalid result, cancellation, timeout or conflict commits nothing.

This is an initial local scripting environment, not a reviewed public plugin security platform. Time is bounded to 5 seconds and result complexity is bounded; worker heap allocation is not strictly metered. Do not describe it as safe for arbitrary hostile code or enable server execution of user scripts. Constructor/command DTO validation alone is not a JavaScript sandbox.

## Plugin boundary

`src/plugins` validates version-1 packages and maintains an immutable registry backed by local browser storage. Installation stores inert data. `editor.runPlugin` resolves only an installed command, invokes the scripting runner, enforces document read/write permission at the host commit boundary, checks revision/assets, and applies one labeled transaction. Plugins inherit the script runtime's time, command and result limits; there is no privileged page-context execution. The React Plugins panel provides package/source review, explicit installation/replacement, run/stop/output, export and removal. See [PLUGINS.md](PLUGINS.md).

## REST boundary

The optional local service binds `127.0.0.1:8787` and checks loopback Host and allowed browser origins. It maintains in-memory document sessions separate from browser tabs. Routes cover document commands/history, asset upload/retrieval and asynchronous jobs with polling/cancellation. `ApiServerOptions.authToken` enables Bearer or X-API-Key authentication (health remains public); an explicitly supplied generation executor owns external provider authorization and billing. No production provider is bundled. These local facilities do not establish public deployment hardening, durable server storage, browser synchronization or server-side execution of arbitrary scripts. See [API.md](API.md) for route-level constraints.

## Local asset analysis

`AssetStore.metadata` owns a queued `MetadataService`; its worker extracts file declarations through exifr and normalizes inert fields. Work is bounded by one concurrent worker and an eight-second deadline. Asset removal/session disposal cancels analysis. Completion is guarded by worker identity; disposal is terminal, message errors fail explicitly, and queue continuation after completion/failure uses a microtask to avoid recursive synchronous failures. Derived results are rebuilt from source blobs after opening a project; no document commands or undo entries are emitted. `AssetInfoPanel` displays origins and exports privacy-filtered sidecars. See [ASSET_METADATA.md](ASSET_METADATA.md) for current coverage, output bounds and remaining hardening work. `LayerMetadata` provides a live OOP handle to authored layer records through `layer.update`; these persist from schema v2 onward, share locks/history, and remain distinct from worker-derived declarations.

## Historical implementation notes

The sections below record successive implementation slices. Earlier schema/status statements describe their original stage and may be superseded by later notes and the current baseline above.

### Layer masks

`LayerMask` stores selection regions or compound closed Bézier geometry plus enabled/inversion/density settings in a mask coordinate plane. Linked masks inherit layer translation; unlinked masks use document coordinates, with optional mask x/y offsets. `maskFromSelection` captures document-space regions using accumulated layer/ancestor translation. The layer patch is a complete mask replacement, validated in core and exposed through scripting/REST. Schema v3 prevents old readers from silently ignoring masks. Masks leave source assets and geometric bounds unchanged.

Canvas/WASM applies coverage to uncached working content after paint previews and before layer styles; group masks apply to composed children. Export uses identical region coordinates, including existing shadow halos. WebGPU uses the shared selection shader and a separate density/inversion pass, after tone/strokes and before styles/blending. Reference content uploaded for vector/text/raster layers has its mask removed to avoid applying it twice. Existing GPU failure/precision fallback remains available. Vector masks rasterize compound paths through Canvas using even-odd or nonzero fill on a fixed 256-pixel coverage grid with a two-pixel halo. Viewport and export strips crop the same coverage tiles to avoid clip-size-dependent curve differences; the GPU caches coverage per layer and uses its existing inversion/density/compositing pass. Coverage is keyed by geometry, fill rule, render region and layer origin. The OOP path getter returns detached copies; capture from a vector layer converts between source/target coordinate spaces. Bitmap-mask import, rotation and scaling remain T06 work.

### Mask feather processing

`engine/masks.ts` generates raw selection/vector coverage with a complete finite-support halo for each at-most-512-pixel output tile. The `featherAlpha` WASM ABI performs three horizontal/vertical fractional box passes with sliding sums and float intermediates; only final alpha is rounded. The pixel worker owns execution and scratch memory. RGBA plus two float planes are bounded by the four-million-pixel working-tile guard before allocation; extreme preview zoom/radius combinations fail explicitly. The final coverage canvas is shared by reference/export rendering and GPU uploads. Canvas and GPU cache coverage independently of inversion/density. The GPU rounds density-adjusted coverage to byte alpha before applying it, matching the reference mask surface and limiting accumulated group differences. Source pixels are never blurred; normal styles and group composition happen afterward.

Mask origin resolution is shared by Canvas and WebGPU through `core/masks.maskOrigin`. Coverage cache signatures use the resolved origin, so parent motion invalidates linked coverage but can reuse stationary unlinked coverage. `Layer.setMaskLinked` converts offsets when changing planes to preserve world position; it emits an ordinary complete mask update with the existing locks/history. Document data is not mutated when an unlinked mask's layer moves. Reparenting and duplication retain the stored plane and offsets.

Direct mask translation uses the existing UI gesture preview boundary: capture the complete initial mask, preview an x/y replacement, and commit one validated `layer.update` on release. No renderer, document schema or REST/script contract changes are required. Keyboard nudges use `LayerMask.with` through the attached layer setter. UI target state is separate from document data; source position and mask linking are unchanged.

Painted masks add `kind: "paint"` with base coverage and validated ordered brush/pencil operations. Coverage replays through the existing stroke rasterizer, clips in the mask plane, and composites Hide with destination-out or Reveal with source-over before feather/inversion/density. Source tile references are disallowed. Canvas/export share this coverage function; WebGPU uploads and caches its result, then uses the existing mask pass. ToolController captures a mask/coordinate snapshot, publishes transient stroke previews at most once per animation frame and commits one full mask replacement via the public value API. Revision checks prevent stale commits. Painted-mask coverage now retains finished prefixes in the shared viewport cache and appends active points to a bounded tile LRU. Feather processing still runs over affected coverage tiles; preview data carries only the active stroke, target layer ID and hide/reveal mode.

### Painted-mask coverage retention

`PaintedMaskRaster` shares the existing 64 MiB CanvasCache for finished prefix/full raw coverage and keeps at most 16 MiB of active raw stamp surfaces (at most 64 entries). This is additional to the existing ordinary paint-stroke 16 MiB surface. Cache keys include mask identity, render space and resolved origin; signatures include base coverage and full ordered operations. A completed full mask can become the next stroke’s prefix. Active coverage checks settings and the entire point prefix before appending, and resets on edits/undo. Clip, opacity, hide/reveal, feather, inversion and density are applied to disposable copies, preventing cumulative clipping or opacity. Cache eviction/oversized surfaces use fresh rendering without changing document data. Export/reference `cache:false` bypasses retention. Clearing the renderer releases active mask surfaces, and epoch guards prevent stale asynchronous jobs from repopulating cleared caches.

A layer’s unmasked content signature omits only its own mask. Group signatures retain descendant masks because those affect the group’s rendered children. Canvas and GPU source textures can therefore survive edits to their own masks without hiding child-mask changes. `CanvasRenderer.maskDiagnostics` reports prefix hits/replays, appended point work and active pixel bytes for verification; these counters are application diagnostics, not a scripting API or hardware speed guarantee.

### Transient painted-mask previews

`PaintPreview.maskMode` distinguishes mask hide/reveal from ordinary artwork strokes. ToolController uses this trusted renderer-only value rather than rebuilding a document command per pointer frame. Canvas and GPU append the active operation only inside coverage rendering, preserving document snapshot identity, history and source content. The target group may reuse its unmasked child composition, but ancestors of a masked child must recompose. The UI may present an older prefix of the same stroke only when document, assets, region, scale, target layer, stroke ID and mask mode still match; cancellation/commit/revision changes invalidate pending previews. Stroke/total-point budgets are checked before and during capture; the final DOM assignment still receives full shared validation.

Selection/vector masks may retain the same ordered brush refinements as a uniform painted base. `maskGeometry` includes kind, base geometry and strokes in coverage signatures, preventing stale caches when either component changes. Raw coverage first rasterizes regions/paths, then composites strokes; prefix caching and transient previews share this ordering. GPU selection shaders are used directly only when no strokes/feather need reference coverage. Shape/path values remain independently editable through the OOP API; no source rasterization or schema migration is needed.

Mask-pen gestures capture the original immutable LayerMask, revision, resolved origin and a detached editable path snapshot. Hit testing uses a seven-screen-pixel tolerance in that plane. Frames publish complete mask command previews at most once per animation frame; release applies `mask.with({paths})` through the attached layer, retaining strokes and mask-wide settings. Cancellation discards previews and revision checks reject stale commits. Keyboard edits resolve the selected mask contour/anchor against the current document; target state is UI-only. Existing layer pen creation remains separate. No schema, REST or scripting signature change is required.

Bézier subdivision uses the pure `core/bezier.ts` De Casteljau helper. Public `VectorPath.splitSegment` commits through existing path validation/history; the mask pen splits detached path copies and replaces the attached mask once, retaining its settings and paint refinements.

Mask contour creation retains a draft across pointer releases, including the original document/revision, immutable mask, resolved origin and new anchors. Each pointer gesture clones the draft points; frame previews append one closed contour to the captured mask DTO. No intermediate anchor enters document history. Completion assigns `LayerMask.with({paths})` inside a single named transaction. Explicit cancellation clears the draft and previews; revision/selection checks reject stale commits, and the UI discards an idle draft when the document revision changes. Contour drafts are transient tool state and are not saved, recovered, exposed through scripting or sent to REST. Those surfaces continue to accept completed closed path geometry.

Mask curve hit testing uses `core/bezier.ts` with pointer-relative screen coordinates. An iterative De Casteljau search bounds candidate intervals by control-point boxes and evaluates actual cubic points. It prunes improvements below 0.01 screen pixels, stops at representable parameter/depth bounds, and shares a 65,536-node work budget across a mask. A work-budget error leaves the document unchanged and suggests zooming in or using Insert midpoint. This is a bounded numerical search, not a symbolic nearest-point solver or an image-resolution limit. Anchor/handle hits precede curve hits. Successful curve hits subdivide only the affected segment in a detached mask preview; release commits through the existing mask update. The insertion is fixed at the pointer-down location; moving the new anchor is a subsequent editing gesture. Cancellation cannot leave a selected transient anchor index referring to a different committed anchor.

`document.crop` delegates to `core/crop.ts`: validate an integer rectangle, rebase root positions and document-space selections/unlinked masks, then retain all local content and assets. It operates on the command executor’s detached document clone, so schema/coordinate overflow errors discard the entire operation. Existing schema-v3 geometry stores the result; no crop bitmap or new project version is needed. ## Adjustment layers and tonal primitives

`AdjustmentLayer` introduces non-destructive, full-stack adjustment layers with `kind: "adjustment"`. Unlike content layers, adjustment layers do not own raster assets or spatial bounds. Instead, they evaluate non-linear transfer functions against the accumulated preceding backdrop stack.

Stack ordering and masking:

- An adjustment layer modifies the accumulated backdrop up to its position in the layer tree.
- Stack bounds: layer masks (selection, vector, or paint) constrain the adjustment's spatial influence. Outside the mask, the backdrop remains completely unchanged.
- **Alpha preservation invariant**: adjustment layers strictly preserve the backdrop's alpha channel. Transparent pixels remain zero alpha and color; semi-transparent pixels retain their exact alpha.

Transfer math and lookup tables:

- **Curves**: Evaluated via monotone cubic spline interpolation (Fritsch-Carlson algorithm in `src/core/adjustments.ts`), ensuring monotonicity between control points and preventing overshoot artifacts. Generates 256-byte lookup tables per channel (RGB master, red, green, blue).
- **Levels**: Evaluated via piecewise transfer functions mapping input black/white points and midtone gamma to output black/white points.
- **Lookup table composition**: Precomputed composite 768-byte lookup tables (R, G, B) allow single-pass evaluation across pixel buffers.
- **Processing space**: Strictly encoded 8-bit sRGB processing space. High dynamic range, 16-bit float, and non-sRGB working spaces remain future architectural milestones.

WASM and WebGPU execution:

- **Canvas/WASM Reference Renderer**: The backdrop region is read back and passed to the compiled WASM kernel (`applyLut` for 768-byte table lookup, `blendAdjustment` for in-place alpha-preserving interpolation).
- **WebGPU Compositor**: Evaluates Tone adjustments and Master Levels natively in the processing WGSL shader (`case 6u` and `case 7u`), preserving backdrop alpha and premultiplied color representation. Non-master (per-channel) levels and non-linear spline Curves trigger clean fallback to the reference CanvasRenderer via `AdaptiveRenderer`.
- **Tonal Histogram**: Bounded 256-bin histogram computation (R, G, B, Luminance using `0.2126R + 0.7152G + 0.0722B`) with mean, median, stdDev, and total pixels statistics. Computed via WASM `histogram` kernel with a pure TypeScript fallback.

### Batch recipe ownership

New batch configurations persist a deep-cloned `recipeSnapshot` alongside `recipeId`. Cost estimation and item execution use this snapshot, so changing or deleting a reusable recipe cannot change an existing run. Missing recipes are rejected before batch creation. Legacy runs with a recipe ID but no snapshot must be recreated explicitly; the runner refuses to infer the historical definition from current recipe storage. Runs without recipes remain supported.

### Batch persistence failures

Browser batch storage requires IndexedDB. Open, write, delete, and read failures propagate to callers; browser reads use durable records rather than the headless memory backend. Writes update memory only after the transaction commits. A worker-pool checkpoint failure aborts remaining workers, waits for them to settle, emits `run_failed`, and makes `waitForRun` reject. The Batch dialog displays the error. The last durable checkpoint remains available for explicit resume; an unsuccessful persistence attempt cannot itself record a new durable status. Headless Node tests retain an in-memory backend.

### Batch execution ownership

Browser start/resume acquires an exclusive Web Lock named for the run and holds it until its worker pool settles. A competing tab fails explicitly instead of interpreting a live run's `running` items as interrupted work. Browser termination releases ownership automatically. Same-instance starts retain deduplication, and resume waits for a previous local ownership scope to finish. Browsers without Web Locks reject execution rather than silently run without coordination. This covers execution ownership only; remote pause/cancel/review mutations require additional coordination.

### Atomic batch updates

`BatchStorage.updateRun` applies a synchronous mutation inside one IndexedDB read/write transaction. Missing records and callback errors reject and abort. Worker picking/checkpointing, pause/cancel, worker-pool finalization, and review edits use this operation; cancelled item state is preserved against late worker patches. Completed manifests are derived from each service read/export snapshot, rather than persisted by overwriting a potentially stale run. This prevents lost updates in these paths. Start/recovery/retry and deletion still require broader lifecycle coordination.

### Batch retry and deletion ownership

Retry acquires the same execution lock as start/resume before resetting failed items. Start/recovery transitions use atomic run mutations and check that preflight has not been superseded by a lifecycle change. Deletion through the batch service rejects active local/remote workers and holds exclusive execution ownership while removing the run and its source/output blobs in one IndexedDB transaction. Deterministic variant blob keys are also removed, including outputs written before their checkpoint. Remote cancellation still needs provider/worker notification and cancellation-output cleanup.

### Cross-tab batch control notifications

Pause/cancel persist their state before publishing a same-origin BroadcastChannel notification. Active owners reread the durable run before applying a pause flag or abort signal, avoiding stale-message cancellation of a later run. Disposing a batch runner closes its channel and aborts local workers. Canvas calls already in progress still settle before ownership is released; abort guards prevent subsequent variants and cancelled item state remains durable. Environments without BroadcastChannel retain durable-state checks at worker picking/finalization but cannot promptly notify an in-flight worker.

### Atomic batch output publication

Rendering returns encoded bytes without persisting them. `commitDeliverable` writes the blob and its item checkpoint in one transaction over runs/blobs, after verifying the item still accepts outputs. Cancelled or removed items reject publication. A post-render abort check avoids submitting known-cancelled bytes; the durable-state check also covers cancellation whose notification has not reached the worker. Previously checkpointed variants remain available after cancellation. This prevents new unreferenced outputs from interrupted publication; deletion still removes legacy deterministic variant blobs.

### Per-document canvas views

The editor UI retains zoom and pan by live Document object identity in a weak map. Explicit Fit and Actual Size actions still reset the active view. Reopening the same project into separate tabs does not share view state merely because serialized document IDs match. ## Retouch tonal kernel foundation

`core/retouch/dodgeBurn.ts` supplies the internal pure `applyDodgeBurn` operation for straight-alpha sRGB RGBA tiles. It returns new pixels, never changes source bytes or alpha, and preserves fully transparent hidden RGB and zero-coverage pixels. A one-byte-per-pixel coverage array represents brush/pressure coverage. Exposure and flow are each in [0,1]. Linear-light luminance L uses overlapping range weights: shadows 1−L, midtones 4L(1−L), highlights L. Signed strength spans at most two stops, scaled by exposure, flow, coverage and range weight. With gain g, the luminance curve is L′=gL/(1+(g−1)L); RGB shares its linear-light scale. Protect tones defaults on and limits the common gain before any channel clips. This is a defined Luma curve, not Photoshop compatibility. Non-sRGB inputs must be converted before use.

The kernel is connected to `PixelProcessor.dodgeBurn(pixels, width, height, options, coverage?)`, which runs it as JavaScript in the existing pixel worker. This method snapshots caller inputs before awaiting worker readiness and transfers only its private pixel copy; it does not detach caller buffers. This is CPU worker execution, not a WASM or GPU retouch kernel. It now renders persistent tonal adjustments through the shared compositor and public DOM/scripting constructors; interactive brush tools remain unfinished. T20 still requires non-destructive stroke storage, sampling controls, preview/commit behavior, healing/patch solvers and performance/browser evidence. The current unit tests establish neutral-ramp monotonicity/direction, neutral-channel equality, alpha/source preservation, zero coverage and input validation; they do not establish complete retouching quality or the healing performance gate.

`engine/retouch.ts` now supplies internal `renderTonalStroke(source, brush, adjustment, space, processor, world?)`. It validates a brush/pencil path using the existing mask-stroke contract, snapshots inputs, renders pressure/hardness/spacing/flow/selection coverage and sends the sampled source tile to the tonal worker. Flow belongs to brush stamp accumulation and is not multiplied again by the tonal kernel; zero flow returns unchanged pixels. Coverage rasterization uses a fixed 256-output-pixel lattice with two-pixel gutters to make request tiling independent of Canvas clip bounds. Temporary coverage canvases are bounded and released per cell. Persistent tonal adjustments now use this bridge against their preceding live backdrop. Additional sampling policies and interactive tool gestures remain required.

Tonal adjustment layers persist in document schema v8. `TonalStroke` is a detached constructor value containing an ordinary validated brush/pencil path and tonal parameters. `AdjustmentLayer.addTonalStroke` appends through shared layer-update commands, preserving masks, inherited locks and undo. The compositor samples the preceding backdrop, applies each stroke in order through bounded working tiles and then applies normal adjustment opacity/mask/blend semantics. GPU capability detection rejects this spatial adjustment kind and uses the Canvas fallback; it must never be treated as a global lookup table. Older document schemas with tonal data reject before migration.

Portable recipe execution through RecipeService captures the active document session generation before repository loading or image decoding. Document activation and service disposal invalidate the generation, including switching away and back to the same document. The private package executor invokes the captured guard after asynchronous preparation and before source installation, alongside existing revision/store/selection checks. Invalidated runs close staged bitmaps and commit no assets or history. Batch execution uses its independent staging document and does not depend on the interactive active session.

Batch estimates compile one plan per item using captured source geometry, final item naming, and merged batch/item parameters. Invalid plans (including enabled AI generation steps unsupported by the synchronous runner) reject preflight before workers start. Conditions that skip those steps remain usable. The dialog and persisted runs share the same filename/duplicate-name transformation. This preflight checks plan executability, not source decoding or package integrity: execution still validates actual source bytes, decoded geometry, installed asset references and commands. Asynchronous AI recipe/batch orchestration remains unfinished.

### Poisson retouch kernel foundation

`src/core/retouch/poisson.ts` implements a four-neighbor Dirichlet solve on selected pixels using matrix-free conjugate gradients with an IC(0) preconditioner per encoded-RGB channel. The geometry-only incomplete-Cholesky factor is shared across channels. The numerical formulation follows [Pérez, Gangnet and Blake, Poisson Image Editing (2003)](https://www.cs.princeton.edu/courses/archive/fall16/cos526/papers/perez03.pdf). Donor pixels must already be aligned to the target; callers supply a padded patch with zero coverage on its outer ring. Holes and disconnected selections use the surrounding target as fixed boundary values. Source guidance transfers donor gradients; mixed guidance chooses the stronger signed gradient per edge/channel. Transparent donor edges fall back to target guidance; transparent targets and target alpha remain unchanged. Coverage feathers the clamped solution against the target. Inputs remain immutable.

`PixelProcessor.poissonBlend` snapshots target/donor/coverage/options before asynchronous readiness and performs the iterative solve through the allocation-free AssemblyScript/WASM kernel in the pixel worker. A TypeScript numerical backend remains the reference. Private donor and coverage buffers transfer without a second structured-clone copy. Its result includes pixels, convergence, maximum channel iteration count and maximum absolute equation residual before RGB clamping/quantization. Defaults are 500 iterations and 0.001 residual in 8-bit RGB units. Exhausting iterations is an explicit nonconverged result, which future tool commits must reject or recompute. Malformed geometry/options and missing padding reject. This is an internal engine API, not a public healing DOM method. Fixed boundary values do not establish arbitrary C1 gradient continuity. Donor selection, non-destructive patch storage, gestures, cancellation during solving and GPU acceleration remain unfinished.

Run `node --import tsx scripts/benchmark-retouch.ts` for a correctness-checked Node reference timing baseline, or append `--wasm` to measure the production numerical backend; it is not browser interaction latency. The initial measurements are in `docs/benchmarks/poisson-kernel-node-2026-09-30.json`. The 128/256-pixel cases exceed the roadmap's 50 ms requirement, so the performance gate remains open.

The IC(0)/WASM comparison is retained in `docs/benchmarks/poisson-kernel-ic0-node-2026-09-30.json` and `docs/benchmarks/poisson-kernel-wasm-node-2026-09-30.json`. Both use unchanged fixtures, tolerance and pixel checks. WASM versus TypeScript regressions cover both guidance modes, irregular masks, varied RGB/alpha and incomplete convergence. WASM memory is host-managed, aligned and reused; out-of-range working-buffer/iteration requests reject rather than truncate. The 256-square median improved from approximately 682 ms (unpreconditioned TypeScript baseline) to 400 ms (WASM IC(0)); this still fails the 50 ms gate and is not a hardware/browser interaction guarantee.

### Local donor-search proposal

`core/retouch/donor.ts` implements deterministic local exemplar scoring. The selection mask marks excluded/damaged pixels. Candidate offsets must keep the selected support and its visible four-neighbor boundary inside the sampled region, avoid all selected pixels, and supply sufficient alpha. Scores compare boundary RGB differences after removing most constant channel offsets (variance plus a 0.01 mean-square color penalty), plus alpha error. Lower score wins; equal scores prefer shorter displacement and then traversal order. The damaged interior's RGB is never used to rank candidates. This is a boundary heuristic, not semantic recognition or a guarantee that an unselected donor is defect-free.

`PixelProcessor.findDonor` captures caller pixels, mask and options before awaiting worker readiness, and transfers private copies. `engine/donor-search.ts` captures the requested layer sampling scope, renders a native-resolution window around the selection and proposes an integer document-space offset. Search radius defaults to 64 pixels and is configurable; it is a local search parameter, not an image import cap. Empty/no-context/no-valid-donor inputs reject explicitly. Abort signals stop future sampling and reject late proposals; disposal of a dedicated processor can terminate an in-flight search. No result mutates assets, document data or history. No public DOM/REST binding, automatic healing gesture or confidence threshold ships with this foundation. Exhaustive candidate scoring still needs performance/corpus evaluation and optimization for larger search windows.

### Healing stroke integration

`renderRetouchCoverage` is the shared fixed-grid brush mask rasterizer for tonal and healing paths. `prepareHealingStroke` captures brush data, selected sampling scope and solver options; renders native coverage and local source pixels; searches intact donor support; and solves a padded patch with fractional coverage applied once. The trusted host `EditorApplication.healStroke(brush: BrushStroke, sampling?, solverOptions?, radius = 64, signal?)` uses the same private guarded encode/install/transaction path as Patch, with a single `Healing stroke` history entry. It never changes the current pixel selection to stage a stroke. The method is an application-host service, not an isolated script or REST binding. The tool creates a stroke on pointer-down, accumulates/smooths pressure points with animation-frame overlay updates, and calls the host on pointer-up. Cancellation/reset aborts the owned signal. Each stroke currently becomes a new adjustment layer; editable source-stroke/donor provenance, review/reselection UI, live solved previews and the full public retouch API remain open.

Retouch operations attach their abort signal to their dedicated pixel processor. Aborting terminates that worker and rejects active numerical requests, instead of waiting for donor search/Poisson completion before discarding results. Shared viewport rendering is not terminated; cancellation still checks after an in-flight render/PNG encode/decode. PixelProcessor disposal is idempotent and rejects readiness as well as queued/active requests, including shutdown before the WASM worker becomes ready. Synchronous message-cloning failures remove the failed pending entry and preserve worker usability.

Donor search uses exact packed 32-bit support checks when all selected pixels have the same target alpha. A blocked-source bitmap represents selected/damaged pixels and insufficient donor alpha; shifted word intersections reject invalid candidates. Arbitrary masks and word/row boundaries retain scalar semantics. Variable target alpha falls back to per-pixel comparisons. Boundary scoring, candidate count and deterministic tie-breaking are unchanged. The scalar reference remains executable for parity verification.

When selected support and visible boundary have the same alpha, donor validation packs both into the checked footprint. After validity is established, candidates cannot improve a zero-score winner unless closer: all score terms are nonnegative. Such candidates still increment the valid-candidate count but skip redundant RGB scoring. The scalar path remains exhaustive, including boundary checks, and parity tests verify identical donor/score/count under transparency and distance ties. Nonzero winners and nonuniform-alpha cases retain their existing scoring behavior.

The pixel worker now supplies a WASM packed-validity backend to donor search. One allocation-free ABI call scans all candidate offsets in dy/dx order and returns a private byte validity grid; RGB scoring, counts and tie-breaking remain in TypeScript. Host validation checks grid geometry, support rows, memory size and aligned buffer layout before copying. Returned validity bytes are detached from reusable WASM memory. Variable-alpha support still uses the scalar path. Actual WASM parity checks compare donor, score, counts and errors against the scalar oracle across irregular masks, transparency and 7/31/32/33/65px row widths.

Healing reuses its captured native donor-search pixels when they fully contain the requested target/donor solver rectangles. Extraction copies detached row-aligned RGBA arrays and validates safe integer geometry and source byte length. Incomplete windows return a miss; the solver renders that rectangle normally. This fallback is essential at canvas edges because artwork can extend beyond the artboard and solver halos must preserve those pixels rather than substitute transparency. Reuse is scoped to one captured preparation, not a persistent cache or live-document read.

`PixelProcessor.spatialFilter` snapshots input pixels and options before worker readiness, transfers only private bytes, and returns an independently owned RGBA buffer. This is an internal working-tile operation, not a serialized smart-filter stack or public scripting constructor. `applySpatialFilter` validates geometry and parameters, lays out aligned WASM buffers, and invokes the allocation-free `assembly/spatial-filter.ts` kernel.

Gaussian blur uses separable normalized Gaussian weights, independent horizontal/vertical sigma, finite support `ceil(3 * sigma)` and float64 intermediate premultiplied encoded-RGB/coverage values. Samples outside the supplied tile are transparent zero; edges are not renormalized. The result is unpremultiplied only at the final byte write, with RGB zeroed when rounded alpha is zero. Unsharp mask compares original encoded RGB to the unpremultiplied Gaussian result, applies amount and per-channel threshold, preserves original alpha, and leaves fully transparent source pixels unchanged. Zero blur support and zero unsharp amount return exact copies, preserving hidden RGB.

The caller must provide the full filter halo and crop it after processing; tests prove equality between whole-image and halo-tiled results, including image boundaries. Sigma is finite/nonnegative with at most 4096 halo pixels per axis; unsharp amount is 0–5 and threshold 0–255. These are internal work bounds, not document/import limits. Scratch storage consumes 32 bytes per pixel in addition to the RGBA tile and weight tables and is subject to the existing WASM memory maximum. Large-support performance is not yet evaluated. Instance stack serialization and renderer/export integration are described below; filter-mask blending is described below; the Inspector controls are described below.

### Smart-filter instance integration (schema 11)

`core/smart/filters.ts` owns strict stack validation and cumulative support. `SmartObjectInstanceData.smartFilters` persists at most 32 uniquely identified entries. GaussianBlurFilter, UnsharpMaskFilter and SmartToneFilter are immutable constructor values; SmartObjectLayer.addFilter/setFilters route attached changes through smartObject.filters. Detached instances validate settings before storing them. Shared command validation/history applies to REST and isolated scripts. ComponentRegistry validates nested master stacks; schema versions below 11 reject the new fields. The outer project container version is unchanged.

CanvasRenderer asks the resolver to preserve active filtered instances; attempting ordinary expansion of a filtered instance rejects rather than silently dropping its filters. Preserved nodes still count their full logical master tree against the expansion budget. For each output tile, the renderer maps its bounds into the native master plane, renders enough original composition for the cumulative filter halo, clips input to the master artboard, runs ordered WASM kernels, then applies instance scaling/affine placement. Output-coordinate integer clips avoid affine tile seams; an extra sampling border avoids clamping at native filter edges. Layer masks and styles apply afterward. Nested filtered masters recurse with a depth guard. Cache scope includes the registry content so nested master filter edits invalidate parents; this is conservative invalidation, not a fine-grained dependency cache.

The internal spatial worker convention described above is unchanged. Rendering uses adaptive output tiles to bound typical native sampling footprints. Before allocating source canvases, padded native regions must fit 4,000,000 pixels and an 8192-pixel edge, keeping transient working surfaces within the WASM memory budget. These are working-tile bounds, not document/import limits. Very large cumulative radii, extreme minification and nested filters remain expensive; requests exceeding the bounds fail before canvas allocation. No viewport approximation or source resampling is stored in the document. Performance evaluation and broader rasterization equivalence remain outstanding. The feature is exposed through constructor scripts/shared commands and the Inspector controls described below.

### Smart-filter mask mixing foundation

`PixelProcessor.mixFiltered(original, filtered, mask, density = 1, inverted = false)` is an internal worker/WASM operation. All arrays are matching RGBA buffers, and mask alpha supplies raw coverage. Effective filter coverage is `1 - density + density * (inverted ? 1 - alpha : alpha)`, consistent with ordinary mask density conventions. It interpolates premultiplied encoded-sRGB color and alpha, then unpremultiplies; it does not preserve original alpha as adjustment-layer blending does. Exact zero/one endpoints retain the corresponding input bytes, including hidden RGB; intermediate results whose alpha rounds to zero have zero RGB. The processor snapshots every caller array before worker readiness, never detaches caller buffers, and returns a new result. Inputs are validated before WASM allocation, including finite density and matching buffer geometry. Model, constructor, rendering and persistence integration is described below. The Filter mask Inspector integration is described below.

### Retained native filter tiles

CanvasRenderer retains exact filtered RGBA and optional original copies in a separate 32 MiB, 64-entry LRU. Under memory pressure it drops original copies before evicting filtered results; a masked render reconstructs a missing original through the existing source renderer without rerunning that tile’s filters. An unmasked render needs only the retained filtered result. Keys include asset-store identity, component identity and padded native tile geometry; signatures include component definitions, filter order/settings and master dimensions. Instance filter-mask changes therefore reuse native results, while edited masters, nested dependencies and filter settings invalidate them. Cache reads and writes copy arrays so worker transfers and asynchronous renders cannot mutate retained pixels. Unlike Canvas round trips, byte retention preserves hidden RGB and alpha exactly. Cache:false bypasses reads/writes. Renderer clearing releases entries and epoch guards prevent already-processing tiles from repopulating the cleared cache. This retention budget does not limit document resolution.

### Uniform filter-mask coverage

Before rasterizing native mask coverage, the renderer conservatively checks paint-mask base coverage, density, inversion, transformed stroke bounds and the full finite feather halo against the padded filter tile. Proven fully revealed tiles use filtered pixels directly; proven fully hidden tiles use original pixels without running filters. Unknown, non-paint or fractional coverage retains full rasterization and mixing. The optimization changes neither document resolution nor tile/cache budgets. Independent browser coverage compares against full rasterization rather than only cache bypass.

Uniform endpoints also select which retained buffers are copied: fully hidden tiles request only original pixels, and fully revealed/unmasked tiles request only filtered pixels. Fractional coverage requests both. Every returned array remains a private copy; selective reads preserve LRU refresh, signature checks and the same retained-byte budget.

Filter-mask finished composites share the existing 64 MiB Canvas LRU. Keys distinguish asset store, component, instance and padded native region; signatures include source/filter definitions, mask settings/transform and conservative paint-stroke support including feather halos. Non-paint masks retain full signatures. Raw prefix caching remains available to ordinary masks but is bypassed for filter masks to prioritize finished composites under this budget. Cache bypass disables both completed and filter-pixel retention; renderer epochs prevent stale publication after clearing.

Feather coverage processes a region of at most 1024×1024 in one job when its entire finite halo fits the existing four-million-pixel buffer budget. Larger/over-budget regions retain 512px subdivision. This prevents native filter tiles just over 512px from becoming four coverage jobs, without expanding document limits or allocation budgets. Translated Canvas brush coverage can retain the pre-existing one-level alpha difference across independently rasterized tile layouts; cache-versus-bypass output remains exact in the production fixtures.

PixelProcessor.mixFiltered captures all three caller arrays synchronously, then transfers those private snapshots to the worker. Filtered and mask snapshots are included in the transfer list, avoiding a second structured clone during dispatch. Caller buffers remain usable, including when inputs change before worker readiness; validation failures leave the processor available for subsequent requests.

The WASM filter mixer recognizes identical visible RGBA inputs as an interpolation invariant and avoids the remaining weighted color math for those pixels. Exact endpoint handling runs first to preserve hidden RGB; intermediate mixtures of two fully transparent pixels still canonicalize to transparent black. Unequal visible inputs retain the original premultiplied arithmetic.

Finished filter tiles can be drawn synchronously from CanvasCache under the compositor's current affine transform and output-tile clip. The cache exposes a draw operation, never the retained canvas, so callers cannot retain or mutate its surface. This avoids an intermediate canvas allocation/copy on hits while preserving LRU refresh. Cache-hit lookup and newly rendered tiles share validated padded geometry; context restoration runs in finally even on cache hits and rendering failures.

Painted-mask replay allocates one scratch surface for its stroke sequence. Each overlapping stroke clears the surface, saves/restores context state, applies its own clip and composites opacity exactly once. Standalone and active-stroke calls still own and release their temporary surfaces. The replay releases its scratch canvas in finally; no persistent cache or memory budget is added.

### Recipe parameter ownership and Unicode delivery names

Recipe parameter maps use own-property lookup and prototype-free dictionaries. Names such as `constructor`, `toString` and `__proto__` are ordinary data keys; inherited properties do not satisfy required parameters or override defaults. Interpolation preserves explicitly supplied keys without invoking prototype setters.

Delivery filename stems are limited to 180 UTF-8 bytes at complete Unicode scalar boundaries, with format extensions appended afterward. Lone surrogates are repaired before collision allocation, so the manifest path and encoded ZIP name agree. Collision suffixes reserve space within the same stem budget. This is a filename portability rule, not an image import limit.

Delivery ZIP exports use the shared ZIP/ZIP64 serializer through an asynchronous Blob-input path. CRC reads are bounded to 1 MiB and yield a task between chunks; empty-entry runs yield every 32 entries. The service verifies each output's full byte length and SHA-256 before retaining its immutable Blob for packaging, avoiding an array of all decoded output buffers. Optional AbortSignal checks reject cancelled work before packaging or download. The batch dialog shows verification/packing status and Cancel export; unmount aborts its export. SHA-256 still allocates one complete output buffer, and final Blob/directory assembly is synchronous: this is cooperative packaging, not a streaming archive or a proven multi-gigabyte memory guarantee.
