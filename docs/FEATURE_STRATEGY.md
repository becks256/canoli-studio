# Canoli Studio feature strategy: a professional editor with inspectable AI

Planning baseline: 2026-09-21. Status: proposed product plan, not shipped features or a release promise. Owner: founder/product owner. Implementation handoff: [roadmap](IMPLEMENTATION_ROADMAP.md), [AI specifications](AI_FEATURE_SPECS.md), [competitive evidence](COMPETITIVE_RESEARCH.md). Current behavior remains defined by [requirements](REQUIREMENTS.md), code, and tests.

## Objective and definition of “Photoshop, but better”

Build a broad, professional browser image editor that can replace Photoshop for progressively more demanding work. Compete on precise manual tools, interoperability, color fidelity, speed, reliability, and extensibility as well as AI. A prompt box attached to an incomplete editor does not satisfy this objective.

The intended advantage is **less repetitive work with more control over the result**. Users should be able to inspect what an image contains, create and edit individual assets, protect source material, compare alternatives, and turn an approved edit into a repeatable workflow. “Better” is a testable ambition, not a current market claim. Broad parity is a multi-stage program; the initial commercial release will explicitly state which workflows and file features it supports.

The strongest initial audience hypothesis is designers and image-production teams producing collections, campaign variants, and product imagery. Wall art and home-decor are useful evaluation cases, not a restriction on the editor or a return to manufacturing quoting. Photographers, illustrators, and general designers need their own evaluation tracks as the toolset expands.

## What the research changes

[Current vendor documentation](COMPETITIVE_RESEARCH.md) already describes generative fill/expansion, reference-guided images, AI variations, harmonization, object separation, editable text recovery, masks, smart objects, and batch tools. Browser delivery, non-destructive layers, and “AI-generated images as layers” are valuable requirements but are not individually unique.

Our differentiation hypotheses are the combination of:

1. **Asset intelligence with evidence:** automatic technical metadata plus reviewed semantic descriptions, OCR, palette, object regions and local search. Distinguish file declarations, measured values, model guesses, and human corrections.
2. **Generation inside a real document:** create backgrounds, objects, textures and effects as separately addressable assets; retain editable text/vectors where truly available; compare results before committing. Never call a flattened picture an editable scene graph.
3. **Protected-content workflows:** preserve product artwork, typography, labels, faces or other user-designated regions through enforced masks and verification. A “keep unchanged” prompt is insufficient.
4. **Recipes with visual quality checks:** turn a successful edit into parameterized batch work with preflight, cost estimates, checkpoints, selective retries and a review queue.
5. **Portable, programmable work:** local projects, interoperable exports, constructor-based scripting, a separate REST surface, and permissioned extensions. Keep deterministic editing useful without accounts or AI credits.

No source audit proves competitors lack this combination. Validate the advantage through task comparisons and customer behavior, not feature-name novelty.

## Three end-to-end differentiating workflows

**Collection production:** import 30 product/artwork images → extract metadata locally → correct descriptions and select protected source regions → build a reusable scene with a generated background/shadow → compare candidates → generate aspect-ratio variants → review low-confidence metadata and preservation failures → export PNG/JPEG plus reviewed sidecars. Required: F01–F04, F09, A01–A07, W01–W05. Initial release covers one image before batch automation.

**Asset creation for a designer:** select a placement region → request a transparent botanical asset using a reference → inspect alternatives on the existing canvas → choose a cutout, refine its mask and color → reuse it as a component across designs. Text remains native text. Required: F02/F03/F07/F09, A03/A04/A11. Transparency and separability are evaluated, not assumed from model marketing.

**Repair and repurpose:** inspect an image's profile and rights declarations → select and heal defects → reconstruct editable text with explicit font substitutions → protect logo/artwork → expand background → compare and export web/print-specific variants. Required: F02/F04/F05/F08/F10/F11 and A01/A05/A06/A08. Print-grade export waits for color-management gates.

## What will count as better

Use a consented benchmark pack spanning product shots, wall art, portraits, multilingual posters, illustration and complex composites. Capture user time, manual corrections, output defects, editability, reload fidelity and cost. Run the same task in Canoli Studio and an appropriate incumbent using experienced users; alternate order to reduce learning bias. Report browser/hardware, editor version, model version and task-specific limitations.

Proposed pilot gates (targets, not results): at least five target users complete three repeated workflows; median total task time improves at least 30% over their normal process; at least 80% of outputs are accepted within two attempts; no source-preservation or project-loss failures in the gate corpus. Report sample size and distribution; a small pilot does not prove market-wide superiority. Do not trade output quality for time savings or count prompting time alone.

## Scope and operating discipline

The founder has roughly 260–520 hours over six months at 10–20 hours/week, before sales/support. The full portfolio exceeds that capacity. Deliver vertical slices and maintain the entire backlog; do not announce Photoshop parity on a six-month schedule. Favor existing parsers, codecs and inference capabilities after license/security/quality review; avoid training a foundation model, operating a GPU fleet, or adding multiple providers before one workflow passes its gates.

Local editing and technical metadata should not require paid inference. Paid generation must have explicit budgets and visible data transfer. Price AI consumption separately from unrestricted deterministic editing, with included allowance or metered credits only after measured economics. No free unlimited generation plan is assumed. Commercial architecture is planned here; no accounts, keys, vendor contract, paid call or cloud upload is authorized by this planning artifact alone.

### Current F11 increment: Photoshop groups and pass-through (2026-10-17)

Editable import now reconstructs supported PSD/PSB nested raster groups, placement/order, ordinary/pass-through modes, opacity/visibility, conservative protection and user pixel group masks. Schema-28 native groups share OO/UI/scripting/REST commands and undo. Pass-through uses real backdrop Canvas/WASM composition; native projects retain full hierarchy/assets. PSD/PSB output now retains supported folder/pixel-mask records with scoped baking and explicit control losses; SVG retains rendered prefix preparation. Own pass-group fill/styles, unsupported Photoshop effects/clipping/blends, editable vector/feather mask controls, broader Photoshop output fidelity, precision/color and full memory/device/workflow gates remain unfinished. This advances F11 without completing its broader portfolio or F14.

### Current F06 increment: authored pressure response

Native strokes now support persisted normalized pressure curves, editable knots/presets, shared Canvas/SVG/supported GPU response and constructor/REST/history/workspace paths under schema 29. Explicit curves include true zero response; absent curves retain prior minima and legacy artwork. Tool settings affect future strokes and remain transient. This pressure-only increment preceded the later tip/tilt, library and symmetry work documented below. Textured tips, mixer/smudge, physical tablets and sustained F06/F14 gates remain open.


### Current F06/W04 increment: saved portable brush presets

Named brush/pencil/eraser/clone/tonal/healing settings, including authored pressure curves and optional foreground color, now have a local transactional library and data-only portable packs. Active settings remain transient; saved values persist independently. Imports install new copies, stale updates reject, and raw backup/recovery avoids silent loss. Subsequent strokes remain self-contained shared-command data. This advances reusable brush workflows; later tip/tilt and symmetry increments are documented below. Textured tips, physical tablet validation, mixer/smudge, the broader personal asset library and sustained F06/F14 acceptance remain open. See [BRUSH_PRESETS.md](BRUSH_PRESETS.md) for exact current contracts and verification boundaries.

### Current F06 increments: authored tips/tilt and mirror/radial symmetry

The sealed tip/tilt increment supplies angle/roundness, spherical pen orientation and response curves with native/SVG/supported-WGSL replay and self-contained schema-30 strokes. Mirror/radial symmetry adds schema-31 affine copy metadata, exact document-space settings, guides/ghost cursors and preset/pack v3 compatibility, while retaining original samples, one stroke, shared commands and source ownership. Complete native/SVG/GPU footprints, mask/master coordinate conversion, selection/flow/opacity, clipping, history and production verification are required; the dated roadmap records actual evidence. Textured tips, mixer/smudge, physical tablet/hardware and sustained F06/F14 acceptance remain open. These staged deliveries do not complete the broad professional-editor objective.
