# Canoli Studio editor requirements

## RAW development workflow in implementation

Trusted `editor.inspectRaw(file, image = 0, control = {})` performs read-only native sensor preflight. It returns the version-1 camera/decoder, sensor/visible/display geometry, selected-image/count, precision, calibration/white-balance, extra-sample and warning/capability report. It changes no document, assets or history. Controls accept AbortSignal and progress with phases inspecting/developing/encoding and a nullable fraction. Inspection needs the local native worker and full-input buffer; queued inspections/development share one application-context lease. Native failure, malformed results, cancellation and throwing callbacks reject and terminate private work.

The internal checked decoder produces owned linear RGB16/grayscale16; explicit conversion consent is required before the private worker returns an sRGB RGBA8 working PNG. The build omits DNG SDK/RawSpeed/external lossy-JPEG DNG and external ICC-file processing. Reported metadata support is not proof of valid sensor payloads, device memory or photographic fidelity. The connected host workflow now retains original/accepted assets, editable master commands, persistence and review/development controls; automated acceptance and remaining gates are recorded in the dated implementation roadmap. See the connected RAW source-ownership section below. These trusted file services grant no isolated Scripts/plugin/REST file privilege or live browser/headless synchronization.


## Recovery failure containment and optional-storage startup

Recovery progress preserves the existing active-document footer behavior. Preserve focused text/caret, selection, native pixels and undo history through pending/saving/saved/error transitions. Errors take priority over the existing project-download indicator; its title still describes actual recovery state. Switching or closing a document must unsubscribe its status, and inactive save completion/failure must not replace the active footer. Closing still awaits the existing recovery flush.

Optional recent files must never prevent manual editor startup when access to the browser storage capability throws. If the capability cannot be read, disclose unavailability; if notification construction or sending fails, retain normal local copies and their committed status. Notifications remain advisory and durable generation checks still reject stale preparations. No instantaneous cross-tab list refresh is promised without notifications; explicit Reload remains available.

Recovery persistence catches synchronous request-setup and callback failures, aborts the complete checkpoint/asset transaction and rejects with the original cause. Keep the previous checkpoint and source bytes; report actionable quota failures without uncaught page errors. The same atomic path is used by the UI and persistence worker.

## Recent local files and resource-aware command search (F01/F13/T22 increment)

Remember successful file-backed raster/project/SVG/TIFF/Photoshop opens/imports and explicit project-download requests as disclosed local copies. Keep up to 20 saved entries and the newest 20 pending preparations, sharing byte storage by content hash. Preserve complete original bytes and file name/type/lastModified; same-named changed bytes remain distinct copies. No original resolution/file-size cap, full-file host hashing buffer or source downsampling. Private worker hashing reads at most 1 MiB per slice, validates replies and supports cancellation/disposal.

Entry/blob updates, deduplication, eviction and reference cleanup must commit atomically in IndexedDB. Copy failure remains separate from successful document I/O, with an actionable Recent files status; never falsely acknowledge a saved copy. Invalid entries remain discoverable beside healthy rows; reject corrupt/missing payloads before opening. Clear/remove invalidate queued/in-flight preparations and advance a durable generation so cross-tab older preparations cannot resurrect removed copies. Already delivered independent files/open documents retain their data. Reopen raster copies as new native-resolution documents; other formats retain existing project or conversion/preflight workflows and consent. Closing/cancelled/changed image targets reject and release private decoded assets.

Command search includes open document sessions and valid recent local copies with stable IDs/categories. Preserve selected resource identity across asynchronous result updates; removal must not silently select/execute another resource. Open documents retain independent selection, view, history and assets. The static Recent files action is rebindable but unassigned by default. No isolated script/plugin/REST file, storage or browser-session privilege is added. Copies are not live disk links, external backups or a substitute for recovery/version history.

## Docked and named workspace layouts (F13 increment)

Workspace layout in the tool rail and command search configures Layers/history and Properties independently on either side of the canvas, including visibility, order and responsive or preferred widths. Same-side panels occupy adjacent columns. Apply, save-as-new/update, rename/delete, explicit defaults and reload must be keyboard accessible and persist locally before publishing a change. Cancel discards draft changes. Always retain rail/command access when both panels are hidden. Visual order and DOM focus order agree; moving a dock retains its mounted state and canvas. Preserve artwork, assets, selection, undo/redo, native output and existing zoom/pan. Fit only visible docks to the window without overwriting stored widths on viewport changes.

Read legacy width preferences without rewriting them. A versioned layout envelope takes precedence, including explicit responsive defaults. Reject malformed/unknown/invalid settings and duplicate names/IDs; failed storage and detected newer-tab settings retain the current arrangement. Recovery is explicit. No default keyboard chord is added; both workspace commands can be rebound in Keyboard shortcuts. Floating/tabbed/vertical docks, portable layout import/export, atomic cross-tab preference transactions and wider F13/F14/device/accessibility gates remain open.

## Reusable linked paragraph styles (F08 increment, schema 40)

Users can create a named paragraph style from selected text, apply it to other frames, update the base from text, rename/delete it, reset local overrides or detach it. Choosing a library entry does not edit the document; Apply performs one undoable edit. Base changes update every linked frame in that document while preserving per-field overrides, content, wrap width and placement. Local edits equal to the current base remain explicit until reset. Deleting/detaching preserves the current resolved formatting. Invalid definitions, missing links, duplicate IDs/names, stale script revisions, changed locked followers and native layout failures reject atomically.

UI, OO, isolated scripts/plugins and strict REST commands share the same behavior. Styles and overrides survive project/workspace history; embedded document scopes remain independent and cross-document copy preserves/remaps needed links without overwriting destination styles. Native pixels and exported resolved typography must match equivalent direct formatting. SVG reports style-link/override loss, while native projects retain full editability. Schema 40 admits libraries/bindings; older roots migrate without new style defaults. Font embedding, based-on/character-run styles, variable fonts/path text and broader language/quality/performance gates remain open.

## Edge-preserving bilateral denoise (F12 increment, schema 39)

Smart filters includes Bilateral denoise with exact paired controls for integer Denoise radius 0–16 px (default 2), Color tolerance 0–255 (default 25), and Denoise strength 0–1 (default 0.5). Preview/Escape, enable/order/remove, locks and single committed undo follow existing controls. Zero in any parameter must preserve unfiltered affine pixels and editable SVG geometry. Invalid/null/nonfinite/fractional radius and unknown options reject through UI/OO/commands and strict REST. Larger neighborhoods/tolerance/strength may soften detail.

Use a complete two-dimensional alpha-weighted bilateral RGB8 mean before instance placement. Preserve center alpha, hidden zero-alpha RGB and original assets/dimensions. Independent equations, controlled fine-noise reduction/edge fixtures, native halo crops/cache/masks, project/PNG round trips and a true 50 MP source verify the increment. Controlled noise results do not establish camera/photo quality, RAW development, high-precision denoise, universal speed or full F12/F14 completion. Broader photographic, device/memory and roadmap gates remain open.

## Median denoise (F12 increment, schema 38)

Users can convert a raster to a smart object and add Median denoise from Smart filters. Radius defaults to 1 native pixel, accepts integers 0–32, and zero restores unchanged pixels. Controls must reject fractional input, support exact typing and cancellable keyboard/pointer previews, and share ordinary history, enable/reorder/remove and lock behavior. The filter removes isolated bright/dark speckles with an alpha-weighted per-channel lower median; it preserves center alpha, ignores transparent neighbors and keeps original assets immutable. Larger radii may remove fine detail; it is not a RAW/develop or complete noise-reduction suite.

OO MedianFilter, isolated scripts/plugins and strict REST smartObject.filters commands share validation/history. Native tiled viewport/export, filter masks, project reopening and original bytes must agree. Legacy documents migrate without injected filters; median values require schema 38 in roots and embedded masters. Higher-precision denoise, real-camera quality evaluation, RAW/lens/merge workflows and the remaining F12/F14 roadmap gates remain open.

## Bitmap projection precision

Large affine bitmap placements must retain native pixels and representable source geometry in raster layers, bitmap masks, textures, native wet reconstruction and filtered projections. Keep the existing Canvas path at ordinary placements; use double-precision sampling when projected coordinates cannot reliably retain subpixel geometry. Axis-aligned image edges retain the established half-pixel tie rule; sheared image edges use actual pixel area. Nearest and encoded-sRGB premultiplied-byte bilinear sampling must use the unchanged original bitmap, with bounded native reads and no source-size intermediate.

Gathering must yield for cancellation and queued UI tasks. A texture batch may have only one numerical native reader active at a time; complete all captures before the existing validated worker conversion. Abort, source replacement/closure, clear and disposal must reject private results and prevent late conversion/publication. Cache retirement alone preserves independent readers. Capture mutable native canvases once and close private bitmap snapshots on success or rejection; never close borrowed original bitmaps. Mask retention distinguishes bitmap identities/dimensions. Verify mirrored/fractional/affine pixels, real oversized textured strokes, native 50 MP source/project preservation, software-GPU parity, full-batch event-loop turns and real production script/undo/reopen behavior. Working budgets are independent of original resolution. This does not establish general latency, process memory, physical-device or complete F14 acceptance.

Mask cache budgets include retained native padding and changing reservations at existing keys.

Verify exact affine/scale/seam pixels, real oversized edits, source-coordinate precision, mutable-prefix invalidation, cancellation/input responsiveness and observed owned Canvas allocations. Textured/wet crop stability, representative quality, sustained/editor-wide latency, hardware/tablet and process-memory acceptance remain open.

Include non-binary fractional zooms and numerical/native vector coverage in lattice tests. Cache resets must not cancel independent direct mask reads; simultaneous readers at the same cache key retain their own exact results, and retiring an in-flight owner releases its buffers after the current read completes. Explicit caller cancellation remains authoritative.

## Rich tools milestone

See [TOOLS_MILESTONE.md](TOOLS_MILESTONE.md) for the acceptance audit. Brush, pencil, clone, Bézier pen and rectangle/ellipse marquee use the shared command/history model. Drag layer rows above/below siblings, into the center of groups, or onto the document-root drop target. Reparenting via the UI preserves document position; dragging a selected group on canvas moves its children together.

Brush controls include color, size, hardness and opacity; pointer pressure changes stamp size. Pencil uses hard pixel-aligned marks. Clone uses Alt/Option-click to set a source, previews sampled pixels while drawing, persists source tiles on release, and supports aligned sampling. Drawing over an image creates a separate paint layer. Vector paths have editable anchors/handles, fill/stroke, close and finish actions. Marquee supports replace/add/subtract/intersect and constrains paint, clone, fill and clear operations. Layer properties include fill opacity, 18 blend modes, color overlay, drop shadow and source/underlying Blend If ranges with four endpoints each, in luminance/R/G/B.

The Developer docs link in both the rail and Scripts panel opens generated, locally served documentation; these pages are included in production builds. Scripts and REST commands represent every new document primitive; REST still has no asset/rendering service.

## Responsive drawing

R16: Brush/pencil previews accumulate input samples without committing or validating the entire document on each movement. Publish previews and start queued drawing work at most once per animation frame; consume coalesced events where available. Render only new stroke segments and reuse unchanged layer content within bounded working-memory caches. A cached preview must match full replay with pressure, opacity, clipping, grouping and styles. Release retains the final endpoint and commits exactly one undo step; Escape, focus loss, pointer cancellation/capture loss and document replacement discard transient work. Changed content, transforms, viewport/scale and history must not display stale cached pixels. Export preserves full-resolution originals and uses the same compositing rules.

## Architectural decisions

1. TypeScript for browser UI, application orchestration, and public DOM classes; React for the UI.
2. AssemblyScript for the initial WASM pixel kernel. It resembles TypeScript but is a different, constrained language. Ordinary npm/React code is not compiled into WASM.
3. Public class handles resolve objects by ID in the current document revision. Plain, versioned data-transfer objects are used for snapshots, files, and worker boundaries; attached state is immutable outside commands.
4. Constructor-created layers are detached until added to a document/group. Ownership, stable IDs, validation, atomic transactions, and undo are enforced centrally.
5. Adaptive WebGPU viewport rendering with retained textures and WGSL shaders; Canvas 2D and a WASM worker provide reference/export rendering and automatic fallback. Public document APIs are independent of the selected backend.
6. Original image assets are held separately from document/history metadata. Duplicate layers share sources.
7. No model/provider API in this milestone. A future AI adapter should produce validated document commands and new assets through the same public API. It must not evaluate generated JavaScript.

## Current practical limits

- Desktop browsers; PNG/JPEG/WebP/SVG/PSD imports and PNG/JPEG/WebP/SVG/PSD exports.
- Working color spaces: sRGB, Display P3, Adobe RGB 1998, Linear sRGB. Bradford chromatic adaptation, CIELAB/CIEXYZ/DeviceCMYK conversions, Delta E 2000 calculations, and soft-proofing gamut warnings are supported. 16-bit float and native CMYK printing channels remain future work.
- No fixed source/canvas megapixel cap. Positive safe-integer document dimensions; 64 layers, 8 group nesting levels, 60 undo entries.
- No fixed image/project byte-size cutoff. Browser decoding, memory and document-manifest allocation (plus JSON/base64 for legacy input) still impose real practical constraints; there is no infinite-size guarantee. Original sources remain resident.
- Manual external project saves plus local atomic recovery checkpoints; see [STORAGE_FORMAT.md](STORAGE_FORMAT.md). Browser recovery is not an external backup or a power-loss guarantee. Source assets retained for undo are released when changing documents.
- Rectangular layer hit testing and isolated groups. Basic text layers and single-canvas artboard resizing are implemented. Prototype PSD/PSB interchange and preflight capability inspection are delivered under ticket T17; arbitrary rotation, RAW, and multi-document workspace remain future work.
- Drawing limits: 2048 operations or paths per layer; 20,000 points per stroke/path; 128 marquee regions; 4096 clone tiles per stroke. These bound metadata complexity, not image dimensions. Paint operations can be removed/replaced through scripting; there is no individual stroke inspector yet.
- Marquee displays component outlines rather than a traced combined contour. Clone previews source pixels from the pre-stroke document using a bounded native-resolution tile cache; final source-tile encoding completes on release. Canvas 2D uses encoded sRGB blending and browser antialiasing; Photoshop parity is not claimed.
- Low-level `layer.reparent` uses the destination group's coordinate system; UI placement through `layer.place` preserves world position. General affine transforms remain future work.

### Layer masks — first T06 slice

Every layer/group supports a non-destructive mask captured from the current rectangle/ellipse selection, including Boolean holes. Properties offers create/replace, enable, invert, paired density slider/number input and remove actions; controls obey locks and support keyboard focus. Changes share constructor scripting, strict REST patches, undo/redo and schema-v3 persistence. Layer-local geometry moves with layers, and masking applies before styles in Canvas/WASM export and WebGPU composition. Closed Bézier paths can also be copied from an attached vector layer; compound masks support even-odd holes and nonzero winding, with detached path editing through scripting. Selection and vector masks now include 0–128 px fractional feathering through the WASM worker, with complete filter halos across export boundaries and a paired slider/input. Masks support independent x/y translation and linking/unlinking with position-preserving toggles; unlinked masks stay fixed through ancestor motion and reparenting. ### Direct mask movement

The Move tool offers a **Move target** selector. Choose Mask to drag the selected layer’s mask anywhere on the canvas without hit-selecting another layer or moving source content. Drag deltas use document pixels in either linked or unlinked mode; linking is unchanged. Arrow keys nudge by 1 px, Shift+Arrow by 10 px. Pointer movement previews, release commits once, and Escape/pointer cancellation discards the preview. Layer/ancestor locks apply. Selecting another layer/document or choosing a tool resets the target to Layer. Mask mode hides layer resize handles; mask rotation and scaling remain planned.

### Mask painting

Properties offers Add painted mask (initially reveal-all), or an explicit Replace with painted mask action for other mask kinds. Brush/Pencil options offer these targets for every mask kind: Layer, Mask · Hide, Mask · Reveal. Strokes obey the existing size/hardness/opacity controls, pointer pressure, selection clipping, locks, cancellation and one commit per gesture. Strokes modify mask coverage only, preserve source content, and persist through project/recovery serialization. Existing inversion/density/feather/link/position controls apply. ### Direct Bézier mask editing

With a Bézier mask selected, choose Pen → Pen target → Mask paths. Existing contour outlines, anchors and control handles appear in the resolved mask coordinate plane. Drag an anchor to move its handles with it; dragging a handle mirrors its counterpart unless Alt/Option is held. Release commits one validated mask update; Escape/pointer cancellation discards previews. Click an anchor, then use arrows (Shift for 10 px) to nudge or Delete/Backspace to remove it. Removing a contour’s last anchor removes that contour, leaving the layer, mask settings and paint refinements intact. Empty clicks create no paths and Delete without a selected mask anchor does not delete the layer. Source-path/layer geometry is unchanged, locks apply, and save/reopen/undo use the existing mask contract. Select an anchor and choose Insert midpoint to subdivide its outgoing segment without changing the curve; the new anchor becomes selected and the operation is one undo entry. Click a contour away from existing anchors/handles to insert a control point at the nearby curve location. The curve is subdivided without changing its shape; the inserted anchor becomes selected after release. Hit tolerance is seven screen pixels at any zoom, and existing anchors/handles take priority. Insertion previews without changing history, commits once on release, and Escape/pointer cancellation discards it. Clicking elsewhere remains a no-op unless New contour is active.

### Drawing Bézier mask contours

Properties → Add Bézier mask creates an empty vector mask on an unmasked layer. An empty mask hides content; the adjacent instruction explains how to reveal it by drawing a contour. Pen → Mask paths → New contour starts an explicit draft so empty clicks in normal anchor-edit mode remain harmless. Click adds a corner, dragging sets mirrored Bézier handles, and Delete/Backspace removes the last draft anchor. Enter or Close contour closes and commits; clicking the first anchor closes after at least two anchors exist. A single-anchor contour can be finished with Enter and edited afterward. The draft previews a closed contour and uses a dashed outline; it does not modify document history or saved project content until completion. Each completed contour is one undo entry, and existing geometry, mask settings and paint refinements remain intact. Even-odd nested contours make holes; nonzero follows winding direction.

Escape, Cancel contour, pointer cancellation, tool/target changes and document/selection changes discard the draft. Revisions and locks are checked before commit, and contour/anchor bounds apply before accepting more points. Existing linked/unlinked coordinate rules apply. Arrow nudging is for committed anchors; drawing drafts use pointer placement and last-anchor removal. Undo cancels a draft before applying the normal document undo. Controls preserve their footprint when entering/leaving drawing mode so the canvas does not shift. Project persistence/export uses the existing vector-mask contract.

### Non-destructive canvas crop — first T07 slice

Crop canvas (C) enters on-canvas crop mode. Drag a new frame or start from a single additive rectangular selection, rounded outward to whole pixels. Precise bounds opens the numeric X/Y/width/height dialog using the current frame when present. Reset and Use rectangular selection actions are explicit; compound/elliptical selections do not masquerade as a rectangular crop. Applying creates one undo entry; cancelling or rejecting a stale dialog changes no artwork. Bounds may extend outside the old canvas. Rotation, straightening and affine transforms remain planned.

Crop translates root layers and pixel selections into the new coordinate plane. Linked masks follow their layers; every unlinked mask origin is rebased, including masks inside groups. Locked content participates in this global coordinate change without losing its locks. Source bytes, source resolution, local path/stroke geometry, effects and off-canvas content remain intact. Save/reopen and PNG output use the new dimensions; a later negative-origin crop can recover the previous framing. Crop/resize and their undo/redo clear transient pen/clone coordinates. No arbitrary image resolution limit is added. UI, constructor scripting and strict REST commands share validation, history and failure atomicity.

### On-canvas crop frames

A crop frame is transient until Enter or Apply crop. Drag inside it to move; drag an edge or any of eight screen-sized handles to resize, with a one-pixel minimum. Drag outside the existing frame or choose New frame to draw another. Shift draws a square or preserves the original aspect ratio when dragging a corner, rounded to whole pixels. Edges resize one axis. Frames may extend beyond the current canvas; the overlay dims the excluded part of the current canvas and draws a thirds grid and pixel dimensions.

Arrows nudge a frame; focused handle buttons use arrows to resize their corresponding edges. Shift increases keyboard increments to 10 px. Delete/Backspace clears the frame without deleting artwork. Escape, Cancel crop, pointer cancellation, window blur, tool changes and document revision/replacement changes discard the frame. Undo first cancels the draft, then performs normal document undo. Numeric-dialog Cancel retains the prior frame; applying the dialog uses the same crop command. Pointer updates are scheduled once per animation frame and the final pointer endpoint is retained even before a scheduled frame runs. No document preview mutation, asset rewrite or history entry occurs before Apply.

### On-canvas layer rotation

A single unlocked layer with geometry exposes a rotation handle above its selection bounds. ### Shared-center selected-layer rotation

The Layers panel offers 90° clockwise/counterclockwise and 180° rotation for multiple selected layers. Selected roots rotate together around the center of their combined geometric bounds in canvas space; selecting a group and its child does not transform the child twice. Parent scale/shear is respected. The operation rejects locked roots and missing geometry and commits in one undo transaction. The on-canvas rotation handle also supports multiple selected layers: it uses the shared geometric center and transforms selected roots, excluding descendants of selected ancestors. ### Shared-center selected-layer scaling

The Layers panel offers 50% and 200% scale actions for multiple selected layers. Scaling operates in canvas space around the shared geometric center and preserves editable source contents. ### Multi-layer corner scaling

Multiple selected layers with editable geometry expose four corner handles. Dragging scales the selected roots in canvas space about the opposite corner; Shift uses a uniform factor. ### Move-tool canvas snapping

Horizontal and vertical matches are chosen independently and displayed as temporary guide lines. Alt bypasses snapping during the gesture. Pointer release commits the snapped movement through existing commands; preview and cancellation do not add history. Mask movement and keyboard nudges are unchanged. With Snap to canvas enabled, Include artwork optionally adds visible stationary artwork edges and centers as snap targets. Rulers: drag the horizontal ruler into the canvas to create a horizontal guide, or the vertical ruler for a vertical guide. Drop outside the document or press Escape to cancel. Enter on a focused ruler creates a centered guide. Creation is one undoable document edit.

### Interactive patch retouching

Patch (`J`) uses an existing marquee selection. Drag on the canvas toward the donor region; a translated selection outline shows donor placement. Release to solve and add one alpha-preserving patch adjustment, with one undo entry. Zero-distance drags do not commit. Escape cancels the gesture or pending operation. Sampling options are current layer, current and below, or all layers (default); detail options are donor gradients (default) or stronger mixed gradients. Invalid donors, changed document/selection, allocation failure or solver nonconvergence report an error without committing. The current preview indicates geometry, not a live solved pixel result. Automatic donor selection and live solved previews remain planned.

### Spot Healing brush

Spot Healing (`Shift+J`) accumulates a brush path and repairs it on release using local donor search and Poisson blending. Size, hardness, opacity, flow, spacing, smoothing and pressure dynamics use the shared brush controls; an existing selection clips coverage. Sampling and source/mixed detail controls are shared with Patch. Search radius defaults to 64 document pixels and is adjustable. Successful strokes create separate alpha-preserving adjustment layers with one undo entry; source images remain unchanged. Escape aborts pending work. The overlay indicates stroke extent, not the solved result. No-donor/nonconverged/stale/cancelled operations do not commit. Donor choice is currently a local boundary heuristic; automatic semantic quality and the performance release gate remain unverified.

The Patch tool (`J`) supports Source and Destination placement modes. Source selects the repair region and drags toward a donor. Destination selects donor artwork and drags it to the repair region. Both retain original selection geometry and source assets, commit a new patch adjustment in one undo step, and support Escape cancellation. Source/mixed gradient guidance remains an independent “Patch detail” control. The translated outline indicates donor location in Source mode and repair location in Destination mode; it is not a solved-pixel preview.
