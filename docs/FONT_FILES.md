# Embedded document font files

Status: F08 implementation in progress. Resource/command/native-container and independent REST paths have unit coverage. Connected native browser checks cover embedding/reopening, isolated metrics, independent leases, workspace worker bytes, cache invalidation, SVG, source-close copy/library placement, source-loss rejection and friendly search/availability. Complete font-file transport/removal and broader automation acceptance are still pending. This is not completion of F08 or the roadmap.

## Ownership and commands

`Document.fonts.files` is a `FontFileCollection`. Its `items`, `length`, iterator and `getById(id):FontFile|null` resolve declarations across the document and every stored embedded scope. `FontFile` is constructed from strict `{id,name,resource}` data, not a mutable alternate document API. IDs are the SHA-256 source/face identity; `family` is the stable native family request. `resource` and `toJSON()` return owned metadata. Attached `name` assignment, `files.add(file)`, `files.remove(file,options={})` and `file.remove(options={})` use shared commands and history. A removed handle becomes detached; Undo restores its identity. Reading or renaming a removed handle rejects.

`font.file.add`, `font.file.rename` and `font.file.remove` are strict shared commands. Metadata carries no source Blobs or native handles. On an attached host, declarations must match separately owned resources before activation. Add is idempotent for an identical identity/descriptor; use rename to change a label. Names contain 1–240 UTF-16 units and cannot be all whitespace. Removing an in-use face requires `{replaceWith:string}`; replacement cannot contain the removed family. Exact tokens in quoted/escaped fallback lists are replaced while retaining the other fallbacks. Shared reflow, inheritance, effective locks and dependent-instance checks apply atomically, including adding a face whose requested alias already occurs in locked artwork.

Document schema **43** admits `fontFiles`; older labels reject even an empty new table. Legacy documents without the field and ordinary installed/missing-family requests remain valid. Root and stored-scope declarations may share an identical resource, but conflicting declarations for one identity reject.

## Trusted asynchronous embedding

`Document.fonts.embed(source:Blob,options:FontEmbedOptions={},control:FontEmbedControl={}):Promise<FontFile>` requires an attached source store and must run outside synchronous transactions. Options are strict `{faceIndex?:number,name?:string,replace?:string}`. Single-face input defaults to face 0; collections require explicit selection. Name defaults to the declared full name, family or “Embedded font”, truncated to 240 units. `replace` optionally replaces an exact existing family request in the same Undo entry as attachment. Without it, embedding does not change existing family requests.

FontEmbedControl extends the source-inspection control with optional synchronous `beforeCommit():void`, used by captured UI owners. It also accepts AbortSignal, active parser timeout (60000 ms default) and phase progress. A throwing beforeCommit rejects; cancellation, store and revision are rechecked after it, without another await before publication. The disposable parser and native validation prepare privately. Before commit, cancellation, store lifetime/identity and the target document revision are rechecked. Malformed sources/options, missing stores, cancellation, stale owners/revisions, parser/native failures and effective locks reject. An observer may throw after an accepted command; the source and accepted history remain intact. Rejected prepared resources remain inert in the owning store until disposal, avoiding invalidation of concurrent imports of the same face. Full source-pool collection remains unfinished.

The store keeps immutable complete originals and exact selected native bytes separately from image geometry/bitmaps. Multiple selected collection faces share their original Blob. Native registrations have independent document-store leases; closing one owner does not unregister another's font. Final release removes the owned registration. Registry identity and descriptor checks detect external native tampering. Owned additions/removals invalidate renderer caches even though adding an already loaded FontFace emits no native loading event.

## Saving and reopening

Native project **5** uses the existing checksummed header with a version-5 marker. Strict font records reference deduplicated payloads by original/render SHA-256 and byte length. Standalone original/native bytes share one payload. Collection originals are retained whole, while each selected face has its own native payload. Font resources retained only by Undo, future states, branches, comparisons or stored masters remain in the save closure.

Reading validates container version, ordered nonoverlapping extents, complete byte coverage, hashes, face IDs, native signatures, descriptor/source agreement and referenced/unused records. `loadProject` reparses each original and compares the canonical selected-face descriptor before exposing its store; activation occurs when a Document attaches that store. Font-free native saves remain version 3 or 4; native versions 1–4 remain readable without font records. Workspace encoding captures descriptors/Blobs before its asynchronous graph transfer and sends no native handles. Workspace envelope and history formats are unchanged.

Cross-document artwork/library copies include required declarations and independently leased sources. Component extraction binds inherited source families. History previews acquire their own native leases. Complete recipe/package/batch transport remains unfinished and must not be inferred from the model/container implementation.

## Independent REST font admission

`POST /api/v1/documents/:id/fonts?expectedRevision=N` accepts binary source bytes with optional strict JSON `X-Font-Options: {faceIndex?,name?,replace?}`. It returns HTTP 201 with the normal id/revision/document snapshot, `file` declaration and `metrics:"estimated"`. Defaults and command semantics match trusted embedding. Invalid input/selection/options or locks return 400; stale revisions return 409 and deleted sessions return 404. Configured API authentication, loopback/origin restrictions and request-disconnect cancellation apply. No arbitrary source-file size cutoff is introduced.

The independent server has a FIFO font-parser queue and disposable Node workers, with a 60000ms active parser deadline excluding queue wait. Cancellation/deletion/server closure terminates active work and prevents publication; the source store separately verifies bytes/identity. It creates no fake native FontFaces and does not claim browser-native layout or synchronize with open browser documents.

`GET /api/v1/documents/:id/fonts` retains its existing `fonts` request inventory and adds `files:FontFileData[]`. `GET /api/v1/documents/:id/fonts/:fontId` returns id/revision/file for a currently declared file; missing/removed files return 404. Add `?source=original` or `?source=render` to download exact complete original or selected native bytes. Source download uses the same API authentication, `Cache-Control:no-store`, attachment disposition and `nosniff`. Originals use `application/octet-stream`, independent of the uploaded type; render bytes use the validated font MIME. Native project delivery retains these sources in version 5. Rename/remove/reuse of existing resources uses the normal strict command endpoint and `expectedRevision`, including ordinary Undo/Redo. A second headless session cannot attach an unowned declaration from the first.

## Editor and output

Document fonts keeps inspection/private preview read-only until **Embed selected face** is chosen. Embedded files have friendly labels, explicit rename/removal controls and normal Undo. Typography and replacement presets use friendly names while storing the stable family request. Installed system fonts are not embedded automatically. The complete original file will be included in projects; source embedding flags/copyright remain declarations, and the user must have sharing rights.

Isolated Scripts and internal plugins receive only currently declared selected render faces through a private initial message. The disposable worker loads its native font set before document/layer constructors run, then removes the raw payload before user execution. It receives no font file chooser, host store, image bytes, credentials or network capability. Missing native worker support rejects instead of returning fallback metrics. Source identities are checked before transport and before accepting results; the existing five-second script budget and host permission/revision checks remain. Trusted `embed` rejects there because no source store is attached.

Raster exports render with owned native faces. Referenced source/native identities are pinned before progress callbacks and rechecked through rendering/encoding; loss rejects even when another document retains the same native face. Explicit host SVG delivery includes complete selected native font bytes referenced by visible editable text in inline `@font-face` resources, with strict generated family/descriptor values. It excludes hidden/unused faces, unselected collection faces and system font files. Text rendered into SVG image portions retains source lifetime checks without adding editable font binaries. Viewer support, shaping and Canvas/SVG differences remain explicit; save a project for originals and use native raster output for the editor's rendered pixels. SVG embedded-font reimport and broader viewer acceptance remain unfinished.

Character runs, arbitrary axis authoring, path text, broader shaping/font/device quality, complete transport/removal acceptance and sustained editor-wide performance remain required.
